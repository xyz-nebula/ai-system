## Первый текстовый срез AI-сервиса

Текущий код позволяет провести текстовые ходы кейса «На следующий день...» в роли Менеджера без командных интеграций. Guard блокирует типовые попытки получить внутренние инструкции; проверка структурированного ответа отклоняет невалидную сделку, известные раскрытия закрытых вводных и ошибку модели до принятия хода. Эти локальные проверки основаны на правилах и ключевых фразах и пока не гарантируют обнаружение произвольного пересказа скрытой позиции. Qwen-адаптер добавляет семантическую проверку; живой путь хода проверен с `qwen3.8-9b-q4`, а полная приёмка судей и тренера остаётся отдельным шагом. Правила сделки ожидают подтверждения Product/Scenario. По умолчанию ответы оппонента, судей и тренера демонстрационные.

Установите зависимости:

```bash
uv sync
```

Запустите сервис и терминальный клиент в разных терминалах:

```bash
uv run uvicorn arena_ai.app:app --host 127.0.0.1 --port 8000
```

```bash
uv run arena-ai
```

Введите реплику Менеджера; `:history` показывает транскрипт и число ходов, `:finish` получает фактический исход, три вердикта и отдельный тренерский разбор, `:quit` завершает локальную проверку без итога. Клиент ждёт ответ хода до 210 секунд, завершения — до 300; для другой задержки используйте `--turn-timeout` и `--finish-timeout` (секунды). Контракты хода и завершения доступны в OpenAPI сервиса по `/openapi.json`.

Для необязательного сопоставления подготовки с поединком передайте локальную карточку:

```bash
uv run arena-ai --preparation-file docs/api/examples/preparation-card.json
```

Карточка может содержать анализ ситуации (`situation_analysis`), стратегическую цель (`strategic_goal`), цель на переговоры (`negotiation_goal`), запланированные вопросы (`planned_questions`), возможные решения (`possible_solutions`) и аргументы (`arguments`). Все поля необязательны, но заполненные строки не могут быть пустыми. Карточка валидируется до подключения клиента и передаётся только в `POST /v1/finish`: оппонент, Guard, Validator и судьи её не получают. Файл остаётся локальным и автоматически никуда не сохраняется.

`POST /v1/turn` принимает снимок от вызывающей стороны и возвращает обновлённый снимок. `accepted` означает принятый ход, `blocked` — сохранённую попытку нарушения правил с безопасной реакцией, `model_error` — непринятый ход с неизменённым снимком и кодом ошибки. В будущем Backend хранит канонический снимок и решает вопросы повторной доставки запроса. Для заблокированного хода снимок хранит исходную реплику и категорию причины. Судьи и тренер получают только безопасное описание категории, без сырого текста попытки нарушения.

`POST /v1/finish` получает тот же снимок и возвращает фактический исход отдельно от оценок навыка. Поддерживаются соглашение, частичное соглашение, отсрочка и отсутствие соглашения. Три судьи получают разные рубрики и одну публичную проекцию поединка; тренер получает отдельный вызов без вердиктов судей. Сбой судьи или тренера отмечается в собственном слоте и не меняет другие результаты. Тренерские наблюдения ссылаются на реплику Менеджера и предлагают изменение для следующей попытки. В демонстрационном режиме вердикты и разбор остаются демонстрационными. Для завершения требуется хотя бы один принятый ход; иначе сервис отвечает 409.

Если передана непустая карточка, успешный тренерский разбор дополнительно возвращает `plan_vs_reality`. Каждый элемент помечается как соблюдённый (`followed`), адаптированный (`adapted`) или не проявившийся (`not_observed`). Первые два статуса подтверждаются принятой репликой Менеджера; для третьего доказательство не выдумывается. Без карточки этот раздел отсутствует, поэтому прежний клиентский сценарий остаётся совместимым.

В интеграционном окружении задайте `ARENA_SERVICE_TOKEN` только через секреты процесса. Тогда `/v1/turn` и `/v1/finish` требуют заголовок `Authorization: Bearer <token>` и отвечают 401 при отсутствующем или неверном значении. Если переменная не задана или пуста, локальные вызовы остаются открытыми. `/v1/info` и `/openapi.json` публичны; значение токена сервис не возвращает.

`GET /health/live` подтверждает работу HTTP-процесса и никогда не обращается к модели. `GET /health/ready` сразу успешен в demo-режиме, а в Qwen-режиме проверяет OpenAI-compatible `/models` и наличие настроенной модели. Неуспешная проверка отвечает 503 с одной из безопасных категорий: `gateway_unavailable`, `invalid_gateway_response` или `model_not_found`. Оба health endpoint публичны.

Зафиксированная OpenAPI-схема, примеры ответов и команда black-box проверки описаны в [`docs/api/README.md`](docs/api/README.md). Black-box сценарий поднимает отдельные процессы AI-сервиса и fake gateway, поэтому для него не нужен живой Qwen.

Автоматическая проверка:

```bash
uv run pytest
uv run ruff check src tests
uv run ty check
```

## Подключение Qwen

По умолчанию сервис запускается в демонстрационном режиме. Для endpoint с интерфейсом OpenAI Chat Completions задайте локально:

```bash
export ARENA_MODEL_MODE=qwen
export ARENA_QWEN_CHAT_URL='http://HOST:PORT/v1/chat/completions'
export ARENA_QWEN_MODEL='MODEL_ID'
```

При необходимости задайте `ARENA_QWEN_API_KEY` в локальном окружении. `ARENA_QWEN_JSON_MODE=json_object` добавляет `response_format: {"type": "json_object"}`; значение по умолчанию `prompt` полагается на инструкцию в запросе. Для переключения reasoning на уровне вызова можно задать JSON-объекты `ARENA_QWEN_FAST_EXTRA_BODY` и `ARENA_QWEN_REASONED_EXTRA_BODY` с параметрами, которые поддерживает конкретный сервер. Таймаут модельного вызова задаёт `ARENA_QWEN_TIMEOUT_SECONDS` (по умолчанию 60), а короткий таймаут readiness — `ARENA_QWEN_READINESS_TIMEOUT_SECONDS` (по умолчанию 3). По умолчанию адрес `/models` выводится из `ARENA_QWEN_CHAT_URL`; нестандартный адрес можно явно задать через `ARENA_QWEN_MODELS_URL`. `/v1/info` сообщает текущий режим и идентификатор модели.

Проверенный 22 сентября 2026 года Model/Infra gateway предоставляет модель `qwen3.8-9b-q4` через OpenAI-compatible Chat Completions. При доступе через локальный SSH-туннель использовалась конфигурация:

```bash
export ARENA_MODEL_MODE=qwen
export ARENA_QWEN_CHAT_URL='http://127.0.0.1:18080/v1/chat/completions'
export ARENA_QWEN_MODEL='qwen3.8-9b-q4'
export ARENA_QWEN_JSON_MODE=prompt
export ARENA_QWEN_TIMEOUT_SECONDS=180
export ARENA_QWEN_FAST_EXTRA_BODY='{"chat_template_kwargs":{"enable_thinking":false}}'
export ARENA_QWEN_REASONED_EXTRA_BODY='{"chat_template_kwargs":{"enable_thinking":true}}'
```

Способ создания туннеля и SSH-данные остаются в локальной конфигурации Model/Infra и в репозитории не хранятся. На этом gateway режим `json_object` не подходит: итог не возвращается в ожидаемом `message.content`, поэтому используется `prompt`. Адаптер принимает чистый JSON или один цельный Markdown-блок `json`; произвольный текст вокруг структуры остаётся ошибкой. Переключение thinking зависит от реализации gateway. Сервис не возвращает сырой ответ модели при таймауте, сетевой ошибке и неверной JSON-структуре. Полная сквозная приёмка судей и тренера остаётся отдельным шагом.
