## Первый текстовый срез AI-сервиса

Текущий код позволяет провести текстовые ходы кейса «На следующий день...» в роли Менеджера без командных интеграций. Guard блокирует типовые попытки получить внутренние инструкции; проверка структурированного ответа отклоняет невалидную сделку, известные раскрытия закрытых вводных и ошибку модели до принятия хода. Эти локальные проверки основаны на правилах и ключевых фразах и пока не гарантируют обнаружение произвольного пересказа скрытой позиции. Qwen-адаптер добавляет семантическую проверку; живой путь хода проверен с `qwen3.8-9b-q4`, а полная приёмка судей и тренера остаётся отдельным шагом. Правила сделки ожидают подтверждения Product/Scenario. По умолчанию ответы оппонента, судей и тренера демонстрационные.

Установите зависимости:

```bash
uv sync
```

Запустите сервис и терминальный клиент в разных терминалах:

```bash
uv run uvicorn arena_ai.app:app --host 127.0.0.1 --port 8000
```

```bash
uv run arena-ai
```

Введите реплику Менеджера; `:history` показывает транскрипт и число ходов, `:finish` получает фактический исход, три вердикта и отдельный тренерский разбор, `:quit` завершает локальную проверку без итога. Клиент ждёт ответ хода до 210 секунд, завершения — до 300; для другой задержки используйте `--turn-timeout` и `--finish-timeout` (секунды). Контракты хода и завершения доступны в OpenAPI сервиса по `/openapi.json`.

Для необязательного сопоставления подготовки с поединком передайте локальную карточку:

```bash
uv run arena-ai --preparation-file docs/api/examples/preparation-card.json
```

Карточка может содержать анализ ситуации (`situation_analysis`), стратегическую цель (`strategic_goal`), цель на переговоры (`negotiation_goal`), запланированные вопросы (`planned_questions`), возможные решения (`possible_solutions`) и аргументы (`arguments`). Все поля необязательны, но заполненные строки не могут быть пустыми. Карточка валидируется до подключения клиента и передаётся только в `POST /v1/finish`: оппонент, Guard, Validator и судьи её не получают. Файл остаётся локальным и автоматически никуда не сохраняется.

`POST /v1/turn` принимает снимок от вызывающей стороны и возвращает обновлённый снимок. `accepted` означает принятый ход, `blocked` — сохранённую попытку нарушения правил с безопасной реакцией, `model_error` — непринятый ход с неизменённым снимком и кодом ошибки. В будущем Backend хранит канонический снимок и решает вопросы повторной доставки запроса. Для заблокированного хода снимок хранит исходную реплику и категорию причины. Судьи и тренер получают только безопасное описание категории, без сырого текста попытки нарушения.

Зафиксированное соглашение остаётся текущим фактическим результатом, но не закрывает `/v1/turn`:
после него можно продолжать уточнения, а новое полное взаимное соглашение заменяет прежнюю версию.
Раунд завершает только внешний `POST /v1/finish`, вызванный Backend по кнопке пользователя или его
пятиминутному таймеру. `--turn-timeout`, `--finish-timeout` и таймауты модельного gateway ограничивают
ожидание отдельных сетевых запросов и не являются таймером раунда. AI-сервис не хранит сессии и не
запускает фоновые таймеры.

Кейс может дополнительно передать `opponent_strategy`: упорядоченные заявляемую, желаемую и
предельную позиции с требованиями для каждой уступки. `SessionSnapshot.state.opponent_progress`
хранит текущую ступень и точное основание последнего перехода, поэтому AI-сервис не держит скрытую
сессию между ходами. Модель может перейти только на соседнюю ступень, процитировав новое основание
из текущей реплики; пропуск ступени, повтор использованного основания и предложение более выгодных
условий без перехода отклоняются до записи хода. Эти поля предназначены для межсервисного обмена:
Frontend не должен показывать пользователю внутренние идентификаторы и прогресс стратегии.

`POST /v1/finish` получает тот же снимок и возвращает фактический исход отдельно от оценок навыка. Поддерживаются соглашение, частичное соглашение, отсрочка и отсутствие соглашения. Три судьи получают разные рубрики и одну публичную проекцию поединка; тренер получает отдельный вызов без вердиктов судей. Каждый вердикт содержит один решающий критерий своей коллегии, цитату принятого хода, наблюдение, эффект и сравнение; публичный комментарий ограничен 120 словами и не содержит ссылок на методические материалы. Невалидный ответ после ограниченных повторных попыток превращается в явный `failed`-слот без замены выдуманным вердиктом. Сбой судьи или тренера не меняет другие результаты. Тренерские наблюдения ссылаются на реплику Менеджера и предлагают изменение для следующей попытки. В демонстрационном режиме вердикты и разбор остаются демонстрационными. Для завершения требуется хотя бы один принятый ход; иначе сервис отвечает 409.

Если передана непустая карточка, успешный тренерский разбор дополнительно возвращает `plan_vs_reality`. Каждый элемент помечается как соблюдённый (`followed`), адаптированный (`adapted`) или не проявившийся (`not_observed`). Первые два статуса подтверждаются принятой репликой Менеджера; для третьего доказательство не выдумывается. Без карточки этот раздел отсутствует, поэтому прежний клиентский сценарий остаётся совместимым.

В интеграционном окружении задайте `ARENA_SERVICE_TOKEN` только через секреты процесса. Тогда `/v1/turn` и `/v1/finish` требуют заголовок `Authorization: Bearer <token>` и отвечают 401 при отсутствующем или неверном значении. Если переменная не задана или пуста, локальные вызовы остаются открытыми. `/v1/info` и `/openapi.json` публичны; значение токена сервис не возвращает.

`GET /health/live` подтверждает работу HTTP-процесса и никогда не обращается к модели. `GET /health/ready` сразу успешен в demo-режиме, а в Qwen-режиме проверяет OpenAI-compatible `/models` и наличие настроенной модели. Неуспешная проверка отвечает 503 с одной из безопасных категорий: `gateway_unavailable`, `invalid_gateway_response` или `model_not_found`. Оба health endpoint публичны.

Зафиксированная OpenAPI-схема, примеры ответов и команда black-box проверки описаны в [`docs/api/README.md`](docs/api/README.md). Black-box сценарий поднимает отдельные процессы AI-сервиса и fake gateway, поэтому для него не нужен живой Qwen.

Автоматическая проверка:

```bash
uv run pytest
uv run ruff check src tests
uv run ty check
```

## Подключение Qwen

По умолчанию сервис запускается в демонстрационном режиме. Для endpoint с интерфейсом OpenAI Chat Completions задайте локально:

```bash
export ARENA_MODEL_MODE=qwen
export ARENA_QWEN_CHAT_URL='http://HOST:PORT/v1/chat/completions'
export ARENA_QWEN_MODEL='MODEL_ID'
```

При необходимости задайте `ARENA_QWEN_API_KEY` в локальном окружении. `ARENA_QWEN_JSON_MODE=json_object` добавляет `response_format: {"type": "json_object"}`; значение по умолчанию `prompt` полагается на инструкцию в запросе. Для переключения reasoning на уровне вызова можно задать JSON-объекты `ARENA_QWEN_FAST_EXTRA_BODY` и `ARENA_QWEN_REASONED_EXTRA_BODY` с параметрами, которые поддерживает конкретный сервер. Таймаут модельного вызова задаёт `ARENA_QWEN_TIMEOUT_SECONDS` (по умолчанию 60), а короткий таймаут readiness — `ARENA_QWEN_READINESS_TIMEOUT_SECONDS` (по умолчанию 3). По умолчанию адрес `/models` выводится из `ARENA_QWEN_CHAT_URL`; нестандартный адрес можно явно задать через `ARENA_QWEN_MODELS_URL`. `/v1/info` сообщает текущий режим и идентификатор модели.

В Qwen-режиме AI-контур по умолчанию делает не более двух внутренних попыток для stateless-вызова
роли, если adapter временно недоступен или результат не проходит схему и предметные проверки.
Лимит задаёт `ARENA_MODEL_MAX_ATTEMPTS` в диапазоне от `1` до `3`; значение `1` полностью отключает
восстановление. Повтор использует тот же неизменный контекст и происходит до фиксации хода или
итогового слота. Блокировка Guard завершает ход сразу; Guard `uncertain` возвращает модельную ошибку.
Если Validator отклоняет ответ AI-оппонента, весь ответ генерируется заново в пределах общего лимита
попыток. После исчерпания лимита сервис возвращает безопасный диагностический код ошибки без
изменения снимка. Это может увеличить худшую задержку роли, но не является повторной отправкой
публичного HTTP-запроса Backend после неоднозначного тайм-аута.

Проверка TLS-сертификата включена по умолчанию. Для временного хакатонного endpoint с самоподписанным или выписанным только на `localhost` сертификатом её можно отключить исключительно для соединения AI-сервиса с Qwen:

```bash
export ARENA_QWEN_TLS_VERIFY=false
```

Не используйте эту настройку для публичного endpoint или постоянного окружения: она отключает проверку подлинности модельного gateway. Предпочтительное постоянное решение — сертификат на внутреннее DNS-имя или IP-адрес gateway.

Проверенный 23 сентября 2026 года Model/Infra gateway предоставляет модель `qwen3.8-9b-q4` через OpenAI-compatible Chat Completions на HTTPS-порту 443 внутри WireGuard. Для успешной readiness-проверки и принятого живого хода использовалась конфигурация:

```bash
export ARENA_MODEL_MODE=qwen
export ARENA_QWEN_CHAT_URL='https://172.16.34.6/v1/chat/completions'
export ARENA_QWEN_MODEL='qwen3.8-9b-q4'
export ARENA_QWEN_JSON_MODE=prompt
export ARENA_QWEN_TIMEOUT_SECONDS=180
export ARENA_QWEN_TLS_VERIFY=false
export ARENA_QWEN_FAST_EXTRA_BODY='{"chat_template_kwargs":{"enable_thinking":false},"temperature":0}'
export ARENA_QWEN_REASONED_EXTRA_BODY='{"chat_template_kwargs":{"enable_thinking":false},"temperature":0}'
```

Адрес доступен только через WireGuard. На этом gateway режим `json_object` не подходит: итог не возвращается в ожидаемом `message.content`, поэтому используется `prompt`. Адаптер принимает чистый JSON или один цельный Markdown-блок `json`; произвольный текст вокруг структуры остаётся ошибкой. Отключённый thinking и нулевая температура дали воспроизводимый структурированный вывод в полном прогоне 23 сентября 2026 года: принятый ход, исход, три судьи, тренер и сопоставление частичной карточки подготовки. Отдельные генерации оппонента всё ещё могут нарушить схему и безопасно отклоняются. Сервис не возвращает сырой ответ модели при таймауте, сетевой ошибке и неверной JSON-структуре.

## Повторяемая оценка живого контура

После запуска AI-сервиса повторите фиксированный сильный сценарий кейса «На следующий день...»:

```bash
uv run arena-ai-eval \
  --api-url http://127.0.0.1:8000 \
  --runs 3 \
  --timeout 300 \
  --output /tmp/arena-live-eval.json
```

Если сервис защищён, команда автоматически использует `ARENA_SERVICE_TOKEN` из окружения и не
записывает его в отчёт. Каждый прогон начинает новый поединок, отправляет две фиксированные реплики
Менеджера, завершает его с частичной карточкой подготовки и проверяет инварианты соглашения,
снимка, трёх судей, тренера и сопоставления подготовки. Проверки не требуют конкретного выбора
судьи или дословного совпадения генеративного текста.

JSON всегда печатается в stdout и дополнительно сохраняется при `--output`. Код возврата `0`
означает, что прошли все прогоны, `1` — что хотя бы один прогон нарушил инвариант, `2` — что
readiness или исходное подключение не позволили начать оценку. Явный `model_error` фиксируется в
соответствующем ходе и не вызывает повтор публичного хода со стороны раннера; внутреннее
восстановление AI-сервиса ограничено `ARENA_MODEL_MAX_ATTEMPTS`. Неоднозначные сетевые ошибки между
раннером и AI-сервисом также не ретраятся автоматически.

Сам раннер и его процессный seam без живого Qwen проверяются командой:

```bash
uv run pytest \
  tests/black_box/test_managed_turn_process.py::test_live_evaluation_cli_reports_a_passing_fixed_case \
  -q
```

## Qdrant и Qwen3 Embeddings

Серверный dev-стек retrieval описан в `deploy/rag/compose.yaml`. Он не использует и не изменяет
существующий LocalAI: Qdrant и embeddings работают отдельными контейнерами. Все порты привязаны к
loopback сервера и не должны открываться в интернет или WireGuard напрямую.

На сервере из checkout `ai-system` запустите:

```bash
docker compose -f deploy/rag/compose.yaml pull
docker compose -f deploy/rag/compose.yaml up -d
docker compose -f deploy/rag/compose.yaml ps
```

По умолчанию используется CPU-образ TEI и `Qwen/Qwen3-Embedding-0.6B`. Первый запуск скачивает
образ и около 1.2 GB весов модели, поэтому readiness embeddings может появиться не сразу. Значения
`ARENA_EMBEDDINGS_IMAGE` и `ARENA_EMBEDDINGS_MODEL` позволяют Infra выбрать другой официальный
образ или размер модели после проверки ресурсов сервера. Для практичного CPU-прогрева batch
ограничен 2048 токенами; при необходимости лимит меняется через
`ARENA_EMBEDDINGS_MAX_BATCH_TOKENS`.

На локальной машине откройте туннель через выданный SSH account:

```bash
ssh -N -T \
  -p 8022 \
  -o ExitOnForwardFailure=yes \
  -L 6333:127.0.0.1:6333 \
  -L 8081:127.0.0.1:8081 \
  farrahovd234@2.26.27.230
```

Пока туннель открыт, полный smoke test запускается локально:

```bash
uv run python scripts/check_rag_stack.py
```

Проверка создаёт уникальную временную коллекцию, строит embeddings тестовых русскоязычных
фрагментов, выполняет semantic search и удаляет только свою временную коллекцию.

Курируемый судейский корпус, проверка исходных выдержек и идемпотентная загрузка в отдельную
коллекцию описаны в [инструкции индексации](docs/judge-corpus.md). Эти команды не меняют LocalAI
и пока не подключают найденные материалы к `/v1/finish`; интеграция судейского поиска идёт
отдельным этапом.
