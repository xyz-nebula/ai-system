# Серверный AI-контур и командная интеграция

Развернуть текущий `ai-system` в отдельном контейнере на доступной через SSH среде
`farrahovd234@2.26.27.230:8022` (приватный адрес среды `172.16.34.7`).
Backend остаётся владельцем кейса, снимка, порядка ходов и завершения раунда.
Изменения других репозиториев и чужих контейнеров не входят в разрешённую область.
LocalAI `172.16.34.6:8080` разрешён для клиентского подключения, но не изменения.

## Условия

- Отдельный compose project, зафиксированные зависимости, непривилегированный процесс.
- AI HTTP слушает только приватный IP на незанятом порту 8000, не `0.0.0.0`.
- Bearer service token генерируется на сервере и не входит в Git, образ или отчёты.
- Используются существующие loopback endpoints Qdrant/TEI; их контейнеры не перезапускаются.
- Health процесса не выдаётся за readiness retrieval или качество модельного ответа.
- Развёртывание обозначается как тестовый стенд с известным отказом конструктивного хода.
- Доступ через VPN/приватную сеть; публичный reverse proxy не меняется.
- Проверки используют согласованные публичные seams: health, turn, finish, OpenAPI.
- Отчёты не содержат токенов, закрытых кейсов, транскриптов и методических payload.

## Этапы

01: упаковка и серверный запуск; 02: проверка публичного API с настоящими зависимостями;
03: согласование и проверка подключения остальных команд.
Для 03 необходимы адреса и версии развёрнутых Backend/Frontend/Audio Engine.
Известная проблема `opponent_unearned_concession` не скрывается и не обходится ослаблением правил.
