# Ограниченное восстановление модельных ролей

Status: ready-for-agent

## Problem Statement

Живой eval на `qwen3.8-9b-q4` показал, что один и тот же валидный контекст может сначала вернуть
невалидный структурированный результат или временную ошибку provider, а при следующем независимом
вызове пройти контракт и заземление. Один такой сбой сейчас обрывает ход либо оставляет отдельный
слот судьи/тренера пустым, хотя вызов модели не меняет состояние поединка и безопасно повторим до
фиксации результата.

## Solution

Добавить общий механизм ограниченных попыток для внутренних stateless-вызовов модельных ролей.
Каждая попытка повторно выполняет ту же роль с тем же неизменным контекстом и проходит полную
структурную и предметную валидацию. Первый валидный результат используется дальше; после исчерпания
лимита публичный HTTP-контракт возвращает существующий безопасный код ошибки.

## Implementation Decisions

- Публичный seam и OpenAPI не меняются: восстановление является реализацией AI-контура до фиксации
  результата хода или итогового слота.
- Число попыток задаёт `ARENA_MODEL_MAX_ATTEMPTS`, по умолчанию `2`, допустимый диапазон `1..3`.
- Повторяются исключение модельного adapter, невалидная схема и результат, не прошедший локальные
  проверки приватности/заземления/правил кейса.
- Валидные `uncertain`, Guard-блокировка и решение Validator `reject` не повторяются: это
  содержательные результаты роли, а не ошибка structured output.
- Для Opponent повторяется только его генерация до Validator. Существующая проверка Validator
  выполняется после первого локально валидного предложения.
- Контекст каждой повторной попытки неизменен; снимок поединка меняется только после полного успеха.
- После исчерпания попыток сохраняется класс последнего сбоя: `*_unavailable` для исключения
  adapter и `invalid_*_output` для невалидного результата.
- Retry внутреннего model gateway не означает retry публичного HTTP-запроса после неоднозначного
  сетевого исхода и не меняет ADR о доставке ходов Backend.

## Testing Decisions

- Подтверждённый seam тестирования — публичные `/v1/turn` и `/v1/finish`.
- Управляемые внешние adapters сначала возвращают ошибку, затем валидный результат; тест наблюдает
  принятый ход или готовый итоговый слот без обращения к внутренним функциям retry.
- Отдельный сценарий исчерпания проверяет прежний код ошибки и неизменность снимка.
- Конфигурация проверяет default, границы и отказ на нечисловом значении.

## Out of Scope

- Retry публичного HTTP-запроса Backend или eval-раннером.
- Изменение схем ответов, публикация сырых ответов модели или количества внутренних попыток.
- Повтор после валидного `uncertain`, Guard-блокировки или Validator `reject`.
- Параллельный запуск трёх судей и метрики provider.
