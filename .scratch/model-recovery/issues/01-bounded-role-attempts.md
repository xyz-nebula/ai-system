# 01: Ограниченные попытки модельных ролей

**What to build:** AI-контур повторяет временно недоступный или невалидный внутренний модельный
вызов в заданном малом лимите, не меняя публичный HTTP-контракт и состояние до полного успеха.

Status: ready-for-agent

- [x] `ARENA_MODEL_MAX_ATTEMPTS` имеет default `2`, принимает `1..3` и строго валидируется.
- [x] Guard, Opponent и Validator восстанавливаются после временного unavailable/invalid ответа.
- [x] Каждый из трёх судей и Trainer восстанавливаются независимо.
- [x] Валидные `uncertain`, блокировка и `reject` не повторяются.
- [x] После исчерпания лимита возвращается прежний безопасный код, снимок не продвигается.
- [x] README объясняет границу retry и возможное увеличение latency.
- [x] Публичные HTTP-тесты покрывают успешное восстановление и исчерпание.

## Comments

- 2026-09-23: Основание — живой eval после исправления преждевременного `partial_agreement`:
  независимые прогоны попеременно получили `judge_unavailable`, `invalid_trainer_output` и
  `invalid_opponent_output`, тогда как прямой повтор Trainer на том же типе контекста прошёл все
  проверки.
- 2026-09-23: Реализован общий bounded-call module и применён ко всем пяти типам модельных ролей.
  Публичная схема не изменилась. Проверка: 92 теста, Ruff и ty проходят.
- 2026-09-23: Живой контроль подтвердил, что retry изолирует временные сбои, но двух попыток
  недостаточно для системной неоднозначности Opponent-схемы. Wire-диагностика второго хода показала
  два валидных JSON подряд, в каждом одновременно заполнены `agreement` и `decision`; Pydantic
  корректно отклонил оба корневым `value_error`. Retry оставлен ограниченным, валидатор не ослаблен.
