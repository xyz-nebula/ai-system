# 07: Полная adversarial-проверка на Qwen

**What to build:** Владелец продукта может одним воспроизводимым прогоном доказать на живой Qwen, что конфликтный пользователь не ломает роль оппонента, не получает уступку за угрозу, сам завершает раунд и получает три сильных судейских вердикта без упоминания методичек.

**Blocked by:** 02: Ролевая устойчивость в конфликтном ходе; 03: Договорённость без завершения раунда моделью; 06: Внутренний Judge Retrieval.

**Status:** ready-for-agent

- [x] Управляемый black-box сценарий воспроизводит мат, повторную агрессию, угрозу увести клиентов, ультиматум и последующее предметное предложение.
- [x] Проверки доказывают сохранение роли, отсутствие ответного оскорбления и общего safety-отказа, отсутствие самовольного окончания и отсутствие уступки только за давление.
- [x] Положительная ветка добавляет необходимую встречную ценность и достигает допустимой договорённости, не делая поединок терминальным до `/v1/finish`.
- [x] Завершение возвращает фактический исход и три независимых кратких вердикта с разными критериями и точными доказательствами из транскрипта.
- [x] Публичная аналитика не содержит методических источников, страниц, ссылок, выдержек, приватных вводных или внутренних ступеней позиции.
- [ ] Тот же набор инвариантов проходит через живой Qwen и сохраняет диагностический отчёт без секретов.
- [x] Полный локальный набор тестов, lint, type-check, OpenAPI и проверка diff проходят после изменений.
- [x] Контрактные материалы сообщают Backend о новых полях снимка и внешнем владении таймером, а Frontend — о запрете показывать внутренний прогресс позиции и provenance retrieval.
