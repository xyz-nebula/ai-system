# 01: Позиционная лестница AI-оппонента

**What to build:** Автор кейса задаёт заявляемую, желаемую и предельную позиции AI-оппонента вместе с основаниями переходов, а пользователь видит согласованное изменение условий только после подходящего встречного действия. Прогресс передаётся в каноническом снимке и не зависит от скрытой памяти `ai-system`.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Конфигурация кейса выражает упорядоченные ступени позиции и необходимые основания уступок, сохраняя совместимое чтение прежней формы правил сделки.
- [ ] Снимок поединка содержит внутренний текущий прогресс позиции и наблюдаемое основание последнего перехода; повторная передача снимка полностью восстанавливает поведение без серверной сессии.
- [ ] Публичный управляемый ход применяет только разрешённый переход и не меняет снимок при невалидном предложении модели.
- [ ] Кейс «На следующий день…» начинает с `4 недели / 130%`, имеет желаемую позицию `2 недели / 120%` и красную черту `1 неделя / 120%` с автоматическим повышением.
- [ ] Новое конкретное обязательство пользователя открывает предусмотренную уступку, а повтор уже известного требования не продвигает позицию.
- [ ] Внутренние названия ступеней, основания и закрытая стратегия не попадают в текст ответа, судейскую аналитику или пользовательские примеры.
- [ ] OpenAPI, совместимые примеры запросов и тесты публичного хода отражают расширенный контракт.
