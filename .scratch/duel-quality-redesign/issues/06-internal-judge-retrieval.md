# 06: Внутренний Judge Retrieval

**What to build:** Каждый судья получает разрешённую методическую опору своей коллегии при завершении поединка, но пользователь видит только естественный минутный вердикт без происхождения внутренних материалов.

**Blocked by:** 04: Сильный минутный вердикт судьи; 05: Курируемый судейский корпус.

**Status:** ready-for-agent

- [ ] `/v1/finish` выполняет отдельный внутренний поиск для каждой коллегии и передаёт судье общее ядро плюс профиль его коллегии.
- [ ] Судейский гайд и практический вопрос коллегии имеют приоритет над тематическими техниками; найденные приёмы не превращаются в счётчик навыков.
- [ ] Доказательством вердикта остаётся точный эпизод транскрипта, а не текст методики.
- [ ] Источники, страницы, `chunk_id` и выдержки используются только для внутренней диагностики и не появляются ни в одном публичном поле ответа.
- [ ] Поиск не получает приватные вводные участников, чужие вердикты или неразрешённые документы.
- [ ] Недоступный Qdrant, embeddings или невалидный retrieval даёт отдельный явный failed-слот без вердикта, сформированного без обязательной методической опоры.
- [ ] Ошибка одной коллегии не подменяет и не отменяет готовые независимые результаты остальных коллегий.
- [ ] Публичные тесты завершения и retrieval-интеграция подтверждают успешный путь, изоляцию коллегий, приватность и безопасный отказ.
