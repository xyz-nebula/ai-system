# 06: Внутренний Judge Retrieval

**What to build:** Каждый судья получает разрешённую методическую опору своей коллегии при завершении поединка, но пользователь видит только естественный минутный вердикт без происхождения внутренних материалов.

**Blocked by:** 04: Сильный минутный вердикт судьи; 05: Курируемый судейский корпус.

**Status:** ready-for-agent

- [x] `/v1/finish` выполняет отдельный внутренний поиск для каждой коллегии и передаёт судье общее ядро плюс профиль его коллегии.
- [x] Судейский гайд и практический вопрос коллегии имеют приоритет над тематическими техниками; найденные приёмы не превращаются в счётчик навыков.
- [x] Доказательством вердикта остаётся точный эпизод транскрипта, а не текст методики.
- [x] Источники, страницы, `chunk_id` и выдержки используются только для внутренней диагностики и не появляются ни в одном публичном поле ответа.
- [x] Поиск не получает приватные вводные участников, чужие вердикты или неразрешённые документы.
- [x] Недоступный Qdrant, embeddings или невалидный retrieval даёт отдельный явный failed-слот без вердикта, сформированного без обязательной методической опоры.
- [x] Ошибка одной коллегии не подменяет и не отменяет готовые независимые результаты остальных коллегий.
- [x] Публичные тесты завершения и retrieval-интеграция подтверждают успешный путь, изоляцию коллегий, приватность и безопасный отказ.

## Comments

- 2026-09-24: создано из утверждённой спецификации переработки качества поединка.
- 2026-09-26: подключён read-only Qdrant/TEI retrieval в configured Qwen-runtime. Все обязательные core/profile загружаются независимо от vector score; тематический запрос зависит только от коллегии. Точные UUID и полный payload сверяются с allowlist; модель получает только текст. При сбое нет вызова судьи и fallback, остальные слоты изолированы. Защита от известных provenance и десятисловного копирования ограничена текстовыми проверками, не гарантирует распознавание произвольного пересказа. OpenAPI обновлён только двумя кодами ошибок; методическая опора не публична. 311 тестов, Ruff lint, type-check, source verification и schema check проходят; формат изменённых файлов проверен отдельно (четыре нетронутых файла имеют прежние отклонения форматирования). Серверный стек не запускался и живой Qwen не вызывался; индексация и живая приёмка остаются в 07.
