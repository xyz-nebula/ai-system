# 01: Eval-раннер фиксированного кейса

**What to build:** AI Engineer запускает фиксированный кейс тимлида через публичный HTTP-интерфейс
`ai-system` и получает JSON-отчёт по повторным прогонам оппонента, трёх судей и тренера.

Status: ready-for-agent

- [x] CLI принимает адрес сервиса, число прогонов, тайм-аут и необязательный путь отчёта.
- [x] Каждый прогон начинает новый снимок, проводит две фиксированные реплики и завершает поединок.
- [x] Отчёт проверяет согласованные инварианты исхода, трёх судей, тренера и карточки подготовки.
- [x] Ошибки одного прогона видны отдельно и дают ненулевой код возврата без раскрытия секретов.
- [x] Black-box тест проходит через отдельные процессы gateway, AI-сервиса и CLI.
- [x] README содержит команды для управляемого и живого повторяемого прогона.

## Comments

- 2026-09-23: Seam подтверждён перед TDD: публичный CLI поверх публичного HTTP-интерфейса;
  внутренние роли и адаптеры не являются тестовой поверхностью.
- 2026-09-23: Реализован `arena-ai-eval`; управляемый процессный прогон проходит восемь
  инвариантов. После ревью отчёт также сохраняет безопасные коды отказов судей/тренера и JSON
  стартового сбоя; данные кейса и общий разбор тайм-аута вынесены из CLI. Полная проверка:
  82 теста, Ruff, ty и committed OpenAPI без расхождений.
- 2026-09-23: До уточнения Opponent-промпта четыре живых прогона подряд завершались
  `invalid_opponent_output` на первом ходе. Структурная диагностика показала валидный JSON и
  контракт, но преждевременный `partial_agreement` без согласия пользователя. После явного запрета
  терминальных `decision` оба хода стали проходить, однако три контрольных прогона по-прежнему не
  дали полного успеха: отдельно наблюдались `judge_unavailable` у ownership-судьи,
  `invalid_trainer_output` и `invalid_opponent_output` на втором ходе. Прямой повтор Trainer на том
  же типе контекста был полностью валиден и заземлён. Это подтверждает необходимость отдельного
  ограниченного retry внутри AI-контура, а не ослабления валидаторов.
- 2026-09-23: После bounded retry и явного взаимоисключения исходов один прогон принял оба хода,
  вернул три готовых судьи, но оформил точное полное предложение как `partial_agreement`, а Trainer
  исчерпал попытки с `invalid_trainer_output`. Следующий прогон исчерпал обе попытки Opponent уже
  на первом ходе. Eval-раннер корректно фиксирует эти отказы; живой контур пока не достиг стабильной
  серии. Следующий структурный шаг — единое discriminated-поле результата Opponent вместо двух
  независимых nullable-полей.
