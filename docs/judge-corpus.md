# Курируемый судейский корпус

Корпус хранится в `src/arena_ai/judge_corpus.py` внутри `ai-system`; вложенный checkout
`knowledge-base` используется только для проверки исходных страниц и не изменяется.
Версия корпуса: `2026-09-26.1`. В ней 15 коротких дословных выдержек.

| Назначение | Источник и страницы | Доступ |
| --- | --- | --- |
| Обязательное ядро: вопрос коллегии, сравнение, причинность, минута, граница Trainer | Судейский гайд, 2, 3, 7, 9, 10, 11 | Все три коллегии |
| Работа под управлением руководителя, уважение и ответственность | Судейский гайд, 4 | `hiring` |
| Доверие переговорщику и эффект действий вместо подсчёта техник | Судейский гайд, 5 | `negotiation` |
| Доверие ресурса, механизм решения и управление рисками | Судейский гайд, 6 | `ownership` |
| Метапозиция без принятия стороны | Подготовка к переговорам, 4 | `hiring`, `ownership` |
| Цель аргументации | Аргументация, 2 | `negotiation` |
| Ожидаемое поведение и обязанности социальной роли | Социальные роли, 8 | `hiring`, `negotiation` |

Кейсы, скрытые вводные, продуктовые примеры аналитики, полные методички и технические
документы не индексируются. Даже в методичке с учебными кейсами разрешены только явно
выбранные теоретические выдержки. Тематические материалы не заменяют судейское ядро и
практический вопрос своей коллегии.

Каждый chunk получает стабильный `chunk_id`, точный текст, `text_sha256`, версию корпуса,
название исходного PDF, записанный в текстовом переносе SHA-256 PDF, путь документа, страницу,
раздел, назначение и список коллегий. Исходные PDF здесь не доступны: проверка подтверждает
точное присутствие выдержки на странице текстового переноса и совпадение его provenance,
а не повторно вычисляет хэш отсутствующего PDF. Эти поля предназначены только для внутренних
проверок и диагностики, не для пользовательской аналитики.

## Проверка исходников без сети

Запускать из корня `ai-system`, где доступны исходные `knowledge-base/methodology/*.md`:

```bash
uv run python scripts/index_judge_corpus.py --verify-only
```

Если исходники находятся в другом checkout, передать его корень через `--source-root`.
Отсутствующая страница, изменённая выдержка или provenance останавливают проверку.
Корпус собирается только из явного allowlist; рекурсивного обхода базы знаний нет.

## Запуск и индексация

На сервере запускать только существующий retrieval-стек:

```bash
docker compose -f deploy/rag/compose.yaml up -d qdrant embeddings
docker compose -f deploy/rag/compose.yaml ps
```

Порты Qdrant `6333` и TEI `8081` остаются на loopback. Для локальной индексации использовать
SSH-туннель из раздела «Qdrant и Qwen3 Embeddings» в README. На локальной машине с исходными
методичками, пока туннель открыт:

```bash
uv run python scripts/check_rag_stack.py
uv run python scripts/index_judge_corpus.py
uv run python scripts/index_judge_corpus.py --check-index
```

Первый шаг проверяет векторы и semantic search во временной smoke-коллекции. Второй
проверяет исходники, строит embeddings через TEI с настроенной в compose моделью
`Qwen/Qwen3-Embedding-0.6B` и записывает одну коллекцию `arena_judge_methodology_v1`.
Документы кодируются без query-инструкции, как в [официальном примере Qwen3 Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B),
и без разрешения на тихое усечение; размер
запроса — одна короткая выдержка. Третий шаг только читает индекс и проверяет, что каждая
коллегия получает ровно своё ядро, профиль и разрешённые темы, а текст, хэши, версия и
provenance каждого payload совпадают с проверенным корпусом.

URL можно задать `ARENA_QDRANT_URL` / `ARENA_EMBEDDINGS_URL` либо соответствующими CLI-флагами.
Не направлять embeddings URL на LocalAI `8080`: этот порт не входит в retrieval-стек и
командами выше не изменяется. Сетевой timeout настраивается через `--timeout`.

## Повторная индексация и безопасный отказ

UUID каждой точки детерминирован из `corpus_id` и `chunk_id`. Повторная загрузка обновляет
те же точки, а не создаёт дубликаты. После успешной записи всех новых фрагментов индексатор
читает только точки с `purpose=judge` и нашим `corpus_id`, проверяет их принадлежность и
удаляет по явным ID только отсутствующие в новой версии chunks. Коллекция никогда не
удаляется и не пересоздаётся. Несовпадение размерности, расстояния или типов payload-индексов
даёт ошибку до записи точек; ошибка embeddings или upsert не запускает удаление старых.

Индексацию выполнять одним оператором между поединками, не параллельно разными версиями
корпуса. Запись и очистка не являются одной атомарной транзакцией: при сбое после upsert
часть старых фрагментов может остаться. Повторный запуск доводит индекс до нужного состояния,
а `--check-index` обнаруживает расхождение. Для диагностики достаточно counts, ID и хэшей;
не передавать внутренние payload пользователю.

Для паузы в работе остановить только эти два контейнера, сохранив данные:

```bash
docker compose -f deploy/rag/compose.yaml stop qdrant embeddings
```

Не использовать `down -v`: это удаляет persistent volumes. Контейнер LocalAI и порт `8080`
в этих командах не участвуют.

HTTP-операции сверены с официальной документацией: [Qdrant points](https://qdrant.tech/documentation/concepts/points/),
[payload indexes](https://qdrant.tech/documentation/manage-data/payload/),
[scroll](https://api.qdrant.tech/api-reference/points/scroll-points) и
[TEI](https://huggingface.co/docs/text-embeddings-inference/quick_tour).
