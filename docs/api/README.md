# Интеграционный контракт AI-сервиса

- `openapi.json` — зафиксированная схема работающего AI-сервиса.
- `examples/managed-turn.json` — безопасные примеры `accepted`, `blocked`, `model_error`,
  продолжения после соглашения и 401. Значения закрытых вводных и service token заменены
  placeholders; внутренняя стратегия оппонента и её прогресс намеренно не показаны.
- `examples/backend-position-turn.json` — отдельный Backend-only пример расширенного контракта
  позиции с вымышленными ID. Поля `opponent_strategy` и `opponent_progress` нельзя передавать в
  пользовательский интерфейс.
- `examples/preparation-card.json` — минимальная локальная карточка для `arena-ai --preparation-file`.
- `examples/preparation-finish.json` — полный пример `POST /v1/finish` с карточкой,
  тремя короткими судейскими вердиктами и проверяемым `plan_vs_reality`.

В файле примеров `case` вынесен наверх, чтобы не повторять его пять раз. Полное тело каждого запроса собирается по правилу `{"case": <top-level case>, ...scenario.request.body}`; это же правило проверяют artifact- и black-box тесты.

Проверить, что схема не разошлась с приложением:

```bash
uv run python scripts/export_openapi.py --check
```

После намеренного изменения публичного API обновить схему:

```bash
uv run python scripts/export_openapi.py
```

Воспроизвести интеграционный сценарий без живого Qwen:

```bash
uv run pytest tests/black_box/test_managed_turn_process.py -q
```

Тест запускает на loopback-портах два независимых процесса: управляемый OpenAI-compatible gateway и `arena_ai.app:app`. Он проверяет readiness, Bearer auth, `accepted`, `blocked`, `model_error`, неизменность снимка при ошибке, продолжение после соглашения и совпадение live OpenAPI с committed-схемой.

Соглашение в снимке — текущий фактический результат, а не сигнал закрытия раунда. Backend и
Frontend владеют пятиминутным таймером и кнопкой завершения; до явного `POST /v1/finish` Backend
может отправлять новые ходы. Сетевые timeout операций `/v1/turn` и `/v1/finish` ограничивают ожидание
конкретного HTTP-запроса и не запускают, не останавливают и не заменяют таймер раунда.
Для `resolution.kind=agreement` пользователь должен явно предложить все обязательства сотрудника
или принять последнее публичное предложение оппонента, где они перечислены. Дополнительные
обязательства директора должны прозвучать в его публичном ответе. Если полного подтверждения пока
нет, оппонент продолжает переговоры с `resolution=null`; прежнее соглашение в снимке сохраняется.

Путь карточки без живого Qwen проверяется отдельно через публичный терминальный клиент и контрактные модели:

```bash
uv run pytest tests/test_cli_preparation.py tests/test_contract_artifacts.py -q
```

Повторяемая оценка живого контура использует те же публичные операции и не обращается к модели
напрямую. Команда и трактовка JSON-отчёта описаны в разделе
«Повторяемая оценка живого контура» корневого `README.md`.
